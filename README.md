# 居家服务组合推荐的证据与目录换版

柜台服务目录和历史办理记录，都是虚构资料。每条原始记录归到本人或带办的其他家庭。observed_id 是柜台当时填入的选项代码，原始用语与代码冲突需复核。资格试算使用合成资格组，所列关系从生效日期开始适用。日期是北京时间。

资料均为合成记录，采用 UTF-8 编码。交换字段、标识和状态见[资料说明](docs/data.md)。

项目使用 Python 3.11.2，资料查看与检测只依赖标准库。在项目目录运行以下命令，可查看各集合的记录数，并检查字段、重复键与跨表引用。

```sh
python3 inspect_records.py
python3 -m unittest discover -s tests -v
```

## 组合证据与目录调整

`service_evidence` 把原始柜台记录整理成“每户一次接洽”的观察，回答两件事：

1. 哪些服务组合在**相同备选集合**下仍超出独立预期的共同选择（可进入柜台建议的依据）；
2. 哪些只是常同时出现（可能来自固定套餐、流行度或整单受理），不应据此调整目录。

```sh
# 生成 JSON 报告（全地区 + 分站证据、柜台建议、映射复核、已发说明）
python3 -m service_evidence.cli --output report.json

# 人类可读版本
python3 -m service_evidence.cli --format markdown

# 顾问工作入口：当前可发说明 / 已发原说明 / 待澄清个案
python3 -m service_evidence.cli --format counselor --household H008
```

分析约定：

* **用语映射按站点与期间生效**。同名用语在不同站点可以是不同含义；两份映射冲突时
  解析为 `pending`，保留候选并列出可能受影响的组合，不替业务人员裁决。
  `reviewed_correction` 只在其自身期间覆盖旧口径，并记录被取代的映射。
* **只统计展示过的家庭**。从未展示某项目的家庭没有选择机会，不作为反例；
  资格也按当日目录版本核查。
* **套餐默认与居民另选分开**。`automatic` 默认不计入选择；历史只剩套餐总项时
  保留总项，不反推子项。
* **一次会话里的多个家庭分开**。借用同一次会话为其他家庭登记的项目不与该会话
  主家庭合并。
* **每户只计一次**。重复接洽、改期或合并单据不重复抬高同一组合的购买次数。
* **多重比较统一校正**。全地区与各站点放进同一族做 Holm 校正；同一组合还会做
  资格范围、全选篮子、套餐默认三项敏感性检查，结论改变时标为脆弱。
* **目录调整提交前**同时核对当前资格、能否分开申请、办理顺序与站点推荐范围；
  只在本站有依据的组合不继承全大类的全区范围。

已发说明分三栏保存：当前可发、已发原说明（只读保留）、待澄清。原说明包含后来
停止单办的项目时，保留当时受理部分的接续处理，新请求按当下目录重新核查。
